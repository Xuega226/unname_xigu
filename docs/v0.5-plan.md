# 未名溪谷 v0.5：券商持仓导入

日期：2026-10-05（Asia/Shanghai）。本次在已验收 v0.4.3 `e32916e` 上完成 `codex/v0.5-acceptance`，版本 `0.5.1+9`。复用本地保留的 v0.5 schema4 源码树 `238cf00d8954cef90b70559b9e3a513d850bdbbe`；后续 v0.6 多账户与历史工作区保持原状。本次结果见 [v0.5.1 验收](v0.5-acceptance.md)，原先 v0.4.2 基线的测试记录保留在 [历史记录](v0.5-validation.md)。

用户尚未确定券商和接口权限。本轮交付通用持仓文件导入与 Windows 前台自动读取；真实券商账户直连仍待明确券商、市场及接口条件，不能把文件读取称为账户直连。

实现与本轮验收已完成：140项测试、双端原生完整磁盘流程、Windows 导出至安卓恢复，以及 v0.4.3 双端发行升级均通过。交付版本为 v0.5.1+9，具体证据、包哈希和未覆盖边界见验收文档。

## 范围

- 中文 CSV / 标准 JSON 读取、账户信息核对、替换预览与确认。
- 单一 CNY 普通股票账户、沪深北六位 A 股代码、整数股数、现金与股票市值。融资负债、其他币种、基金、债券、衍生品暂不支持。
- JSON 首次人工确认后，Windows 可绑定同一文件，每 15 秒前台检查外部工具写入的新完整快照。Android 支持文件导入，不自动轮询本地文件。
- 全账户更新持仓、现金与估值日期；保留研究、累计入金、累计出金和风险偏好。切换账户须核对原有资金流口径。
- 导入来源、账户别名、快照时间、获取时间、SHA-256 和人工修改状态进入备份；绑定路径只保存在本机独立设置。
- schemaVersion 4 兼容旧 v1/v2/v3，迁移前保留对应原始文件。

## 验收

1. 六位代码前导零、带引号 CSV、UTF-8 / BOM UTF-16 均能读取；可用股数不能代替总持仓，成本价不能代替市价。
2. 错误数量、重复代码、代码交易所冲突、未来日期、非完整快照和不支持的账户类型拒绝，旧持仓不变。
3. 首次预览显示新数量、原数量、将移除项、现金和资产；取消及未勾选核验不保存。
4. 自动读取同账户新快照；未变化不重复写入，失败保留旧记录并重试，停止后的在途读取不得写入。
5. 旧日期/旧时间、相同时间不同内容、账户切换、空持仓与人工修改不得直接自动覆盖。
6. 手机、桌面布局及回归检查；Windows / Android 发行构建。真实账户联调单独记录为待完成。
7. 首次已有资金流或来源改变须显式确认归属；全部持仓与移除项每页25项可完整预览，非法日期/时间/时区及损坏元数据拒绝。
8. Windows 实际导出的同份 schema4 JSON 在安卓恢复，资金、来源、财务负值、公告出处和历史保留；恢复成功关闭文件绑定，取消/失败不改变旧绑定。旧 schema3 主文件和仅剩备份均先归档精确原文，再迁移。
9. 双端 v0.4.3 发行包升级保留原研究与 PDF，提交、推送本轮分支并提供可审阅草稿 PR。

## 直连所需信息

券商名称、账户市场与类型、官方只读接口或本机终端接口的可用性。拿到信息后验证登录/授权、资产口径和持仓完整性，再实现适配器输出统一 JSON。不要在聊天、研究备份或日志中填写券商密码或接口密钥。

完整文件约定见 [持仓导入说明](broker-holdings-import.md)。
