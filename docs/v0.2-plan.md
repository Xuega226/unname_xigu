# 未名溪谷 v0.2：下一轮计划

状态：已实施，2026-10-01。两端共用代码，真实行情已验证；DeepSeek 本地配置及草稿核验已实现，真实密钥鉴权与生成需配置后验证。实际结果见 validation.md。

## 本轮目标

让用户能用真实的少量自选公司完成一次“录入资料 → 更新价格 → 生成有出处的研究草稿 → 核验 → 查看账户风险 → 留下复查记录”的流程。

Windows 优先完善操作效率，Android 同步支持核心流程。一开始以 5—10 家自选公司验证，不进行全市场自动排名。

## 必做内容与验收

| 内容 | 交付行为 | 验收条件 |
| --- | --- | --- |
| 正式更名 | 两端应用标题、安卓桌面名称、Windows 文件描述、图标风格与发行包名称统一为“未名溪谷” | 升级安装后原有研究、持仓和复查记录仍可读取 |
| 真实自选公司 | 按代码添加公司，记录交易所、名称、行业和来源；模拟工作区继续明确区分 | 代码保留前导零，名称与市场能核验，演示内容不混入真实工作区 |
| 行情更新 | 接入一个经验证可用的数据来源，手动刷新自选与持仓的日行情或收盘价格，保留估值时间、数据来源、获取时间与状态 | 超时、缺失或陈旧数据明确显示；不同交易日期的价格不被默认为同一时点；断网仍能查看旧记录 |
| 结构化财务录入 | 增加营收、扣非净利润、经营现金流、现金及有息负债等指标的录入模板，保留报告期、披露日期、单位和来源 | 缺失值不当作零；期间不一致不直接比较；特殊行业指标单独解释；先人工核验而不依赖模型自由生成数字 |
| AI 研究草稿 | 用户提供公告或财报文本片段及来源，手动触发分析，输出事实、支持理由、反面证据、缺失信息和复查条件 | 每项事实可定位到输入片段；引用不在输入中则标记无效；无资料时不生成完整结论；人工确认后才保存为研究卡版本 |
| 双端升级与备份 | 共用数据结构与接口定义，Windows 完成录入和比较，Android 完成阅读、更新与复查记录；保留导入导出 | v0.1 备份可迁移，升级不丢数据；两端用同一组输入得到一致风险结果；新版本两端完成构建和运行验证 |

## 关键实现约束

- 产品显示名称与数据存储身份分开。保留已有 Android applicationId；Windows 改名不直接切换旧存储目录，或提供经过验证的迁移路径。
- 对财务指标和引用片段使用稳定 ID。结构化财务字段可能需要升级备份格式，必须实现 v1 到新格式的迁移。
- 数据接口及模型服务先进行实际可用性验证，再绑定产品流程；来源、访问权限、接口成本及各端兼容性未验证前不承诺覆盖范围。
- AI 服务密钥通过本地设置录入，不写入源码、应用发行包或研究备份；保存方式单独设计，错误输出和日志不展示密钥。
- 先接入一种模型接口和一种行情来源，采用手动触发，不增加自动后台轮询。
- 股票和账户计算仍由确定性代码完成。AI 负责整理已提供资料，不直接改变持仓或生成自动交易指令。
- Android 的联网功能不默认依赖 Windows 电脑开机。可共用接口约定，但如果选择 Python 服务，需要提供手机可访问的服务部署方式；尚未确定部署方式。
- 任一网络功能失败时保留旧记录，并展示来源时间与错误状态。

## 推荐实施顺序

1. 更名与升级数据迁移验证。
2. 真实自选股、行情适配层与更新时间展示。
3. 财务字段、来源片段和人工核验流程。
4. 模型接口配置、带引用的 AI 草稿及接受保存流程。
5. Windows / Android 体验包、备份兼容及回归检查。

## 后续范围

云端自动同步、账户登录、后台提醒、完整 PDF/OCR 自动解析、全市场选股、量化回测与自动交易暂列后续迭代。Android 实机验证需要实际连接设备；模拟器结果须单独标记。

## 最终验收任务

任选一家公司，提供带出处的资料并更新价格；生成可追溯的研究草稿；人工接受后写入研究卡；查看相应持仓风险；追加复查记录；在另一端通过备份导入恢复同样的数据。全过程出现资料不足、接口失败或引用无效时，用户能明确看到状态。
