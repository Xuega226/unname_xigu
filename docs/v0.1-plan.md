# A 股选股与风控助手：v0.1 需求

## 已确认的使用目标

- 市场：A 股。
- 使用者：投资经验较少，具备基础 C/C++ 编程知识。
- 持有计划：约一年，可以延长；一年作为复查节点，不自动触发卖出。
- 第一版目标：选股研究与账户风控。
- 目标平台：Windows 和 Android。
- 风险偏好输入：暂时亏损约 20%。暂按整个投资账户相对净投入本金的亏损理解，仍需在使用前确认口径；这是偏好参数，不是实际亏损上限保证。

## 第一轮范围

先手动录入 5 家公司的公开资料与模拟持仓，用同一套流程检查输入、计算和研究输出。5 家是流程验证样本，不代表建议持仓数量。尚未选定实际公司。

第一轮交付物：公司研究卡、账户风险报告、投资假设与复查日志。数据接口、全市场筛选、回测与自动下单留到后续迭代。

## 公司研究卡

每张卡必须回答以下问题：

1. 公司靠什么赚钱，主要经营驱动是什么？
2. 最近三年及最新定期报告的盈利、经营现金流、债务有什么变化？
3. 当前估值适用什么指标，比较对象与统计日期是什么？
4. 未来一年需要验证哪些经营指标？哪些变化有公开依据，哪些仅是假设？
5. 支持理由、反面证据、缺失信息分别是什么？
6. 什么事实出现后，需要重新评估投资判断？

结论使用“继续研究 / 暂缓研究 / 资料不足”。结论不直接转换为买卖指令。银行等特殊行业采用单独的指标解释，不把所有行业套入同一套阈值。

每项关键数字记录：股票代码、指标名称、数值、单位、报告期、披露日期、原始来源、来源页码或章节、录入日期。股票代码按文本保存，保留前导零。缺失数据保留为空，禁止当作零计算。区分年度与季度累计口径，禁止直接比较不一致的报告期间。

## 账户风险报告

最低输入：现金、各持仓代码与行业、数量、同一估值日期的价格、累计入金、累计出金。实盘数据未提供前，仅使用明确标记的模拟数据。

确定性计算：

- 个股市值 = 数量 × 价格。
- 账户资产 = 现金 + 各持仓市值之和。
- 净投入本金 = 累计入金 − 累计出金。
- 相对本金盈亏比例 = (账户资产 − 净投入本金) / 净投入本金，仅在净投入本金大于零且资金记录完整时计算。
- 个股占比 = 个股市值 / 账户资产。
- 行业占比 = 同行业持仓市值合计 / 账户资产。
- 股票总仓位 = 股票市值合计 / 账户资产。
- 指定持仓压力测试 = 持仓占比 × 假设跌幅；其他资产不变。组合情景按各持仓的假设涨跌幅加权，结果只描述指定情景。

账户高点回撤需要历史序列。存在入金或出金时，必须先用单位净值或其他明确的现金流调整方法处理；只有当前余额时显示“历史不足，无法计算回撤”。相对本金亏损与高点回撤分别展示，不互相替代。

20% 偏好先用于展示当前亏损与偏好的差距，不生成自动交易指令。单股、行业和总仓位提醒阈值由使用者设置，在未配置前只展示实际占比。停牌、跳空和无法成交可能使实际亏损超过提醒值。

## 复查日志

- 每月复查一次；新财报与重大公告出现时补充复查。
- 记录原始判断、预期验证日期、新证据、反面证据、判断是否改变、下一次复查日期。
- 一年到期时评估原始判断的实现情况与继续持有的依据，避免仅因浮亏而延长持有。
- 保留旧记录，不用最新结论覆盖过去的判断。

## AI 与程序的职责

程序负责数值计算、输入校验、来源字段完整性检查。AI 根据提供的资料解释业务、整理支持理由与反面证据、列出缺失信息，并引用资料位置。AI 无证据时明确回答无法判断；AI 输出需人工核验。第一轮先使用固定分析模板，尚不依赖模型 API。

## 两个平台的开发安排

采用“从开始考虑双端，Windows 优先完善，Android 尽早验证”的顺序。一套共享的数据结构与业务规则，分别适配桌面和手机的操作方式。

已按用户确认采用 Flutter / Dart 作为两端界面与基础计算实现，开发环境已配置到项目目录。Python 继续作为后续数据采集与分析的候选工具，独立于界面；不假设 Windows 的 Python 程序能够直接打包到 Android。

- 首个应用原型：在 Windows 跑通研究卡、持仓录入与风险计算，同时在 Android 真机验证一个最小流程：打开示例研究卡、查看模拟风险报告、保存并重新打开记录。
- Windows 优先：资料录入、多公司比较、报告导出。
- Android 逐步补齐：研究卡阅读、风险查看、简短复查记录；小屏使用卡片或详情页，避免直接缩放桌面表格。
- 引入文件、数据库与网络等依赖之前，验证它们支持两个目标平台；文件位置通过平台接口获取，不写死 Windows 路径。
- 两端运行与两端数据同步是不同需求。初版建议通过导入与导出手动交换数据，使用稳定记录 ID 和格式版本；自动同步、账号、冲突处理在后续单独设计。
- 若手机后续调用部署在电脑上的 Python 服务，电脑必须运行且网络可达；若要求手机独立运行，则需要远程服务或可在手机执行的计算实现，不能把电脑本地服务视为随处可用。

## 开发顺序与验收

本原型已完成。用户确定下一轮正式更名为“未名溪谷”，后续范围以 [v0.2 计划](v0.2-plan.md) 为准。

1. v0.1：定义录入模板，以手动资料与模拟持仓完成 5 家研究卡、风险报告和复查记录。
2. v0.2：开发共享数据结构与基础风险计算，完善 Windows 界面，同时验证 Android 最小流程；基础公式可在客户端运行，Python 分析模块按需要另行接入。
3. v0.3：完善 Android 的阅读与复查操作；按已确认的数据来源接入行情与财报更新，记录数据日期、错误和缺失项；自动更新不得覆盖研究日志。
4. 后续：有明确筛选规则后再进行回测，按实际披露时间使用数据，并纳入交易成本与成交限制。

v0.1 验收条件：关键数字可查回原始来源；缺失值不生成结论；公式结果可手工复核；每家公司都有反面证据和复查条件；模拟数据不会被显示为真实市场数据；所有未实现功能明确标记。

当前进度：已实现共享 Flutter 原型，包括研究卡编辑、账户设置、持仓维护、基础风险计算、复查日志、本地 JSON 保存与备份导入导出。Windows 发行构建及启动保存验证已完成，Android 构建与设备验证结果见项目验证记录。当前使用 5 张虚构研究卡与模拟持仓，尚未获取真实行情、选择实际样本公司或接入模型。
