# 量化与风险能力接入路线图

日期：2026-10-05（Asia/Shanghai）。最初基线为 v0.5.1+9；用户要求保持单账户，并在风险分析中加入图表。原 v0.1/v0.2 只将筛选、回测列为后续，未绑定交付版本；本文明确后续接入顺序。v0.6 风险图表已完成，v0.7 可配置因子规则与数据基础已实现，结果见 [v0.6.1验收](v0.6-acceptance.md)和 [v0.7.1验收](v0.7-acceptance.md)。v0.8 及以后仍为规划。

用户已明确量化需求为“因子/规则选股与评分”。该需求在 v0.7 正式接入，不以实盘信号或自动交易为首轮目标；具体指标、权重和筛选条件由后续策略配置确定。

## 阶段

| 阶段 | 交付目标 | 前置条件与完成标准 |
| --- | --- | --- |
| v0.6 | 单账户风险图表、可恢复导入、CSV兼容 | 基于已核验持仓与同日价格完成资产构成、集中度、压力情景、本金盈亏图；双端数值一致、导入可撤销 |
| v0.7（已实现） | 量化研究入口：用户规则、因子计算、筛选与评分 | 可配置规则、参数、排除条件与观察日，示例默认不启用，用户核对参数后才计算；展示证据、缺失与贡献，不依赖券商直连 |
| v0.7 数据基础（已实现） | 历史行情、按披露时点的财务和带日期资金流 | 未复权日线、观察日前的整年度原披露财务、独立股本证据及期初累计资金保留；未覆盖期间明确未知 |
| v0.8 | 一项确定规则的回测与图表评估 | 在历史数据可用且策略规则确定后，纳入成本、成交限制与时间可用性；结果可重现，可核对每次信号和模拟成交 |
| 后续独立需求 | 真实只读信号接入、自动交易或更大选股范围 | 券商权限、数据完整性、部署方式及具体策略分别明确；自动交易不因完成回测而默认启用 |

以上为版本里程碑，不是日历工期承诺。主人已确认 v0.7 先做可配置工具、示例默认不启用；应用提供明确的命中权重评分公式与仅筛选模式。示例不代表用户策略，最终参数需主人在应用中确认；v0.8 回测仍为后续阶段。

## v0.7 量化研究入口

策略配置至少说明选股范围、指标定义、观察窗口、阈值或权重、缺失值处理、复查/调仓规则和信号时点。指标值由程序计算，AI 可以解释已有计算与资料，不任意生成因子值或覆盖规则。

首轮延续少量自选公司验证。展示公司原始值、来源、适用报告期间、实际披露日期、规则命中/不命中及资料不足。缺失数据不得默认为0或因缺数据给出高分；银行等特殊行业不强行使用不适用指标。仅在用户核对参数并确认启用后展示综合分和排序，并保留最近20版参数。具体定义见 [量化规则](quant-rules.md)；当前只有日期的资料与行情严格不含观察日。

交付内容包括规则编辑、筛选结果表、综合分及分项贡献图、公司间因子对照和资料缺失提示。可配置指标候选覆盖盈利、增长、现金流、偿债与估值，最终使用哪些指标由策略参数确定；缺少总股本、每股指标或可比期间时，不用用户持仓数量代替公司总股本推算估值。排名显示比较样本范围，不将少量自选排序称为全市场排名。

验收以固定虚构公司与可手算规则为基准：改变阈值或权重会改变筛选/评分且能解释原因；缺失或不适用指标明确显示，参数保存、重新打开与跨端备份后结果一致；同一来源数据和同一规则版本产生相同结果。分项贡献图须与实际评分公式一致，不能只画装饰性雷达图。

量化结果入口与公司研究卡、人工核验和复查记录关联。选股评分不直接变成买卖指令；行情或持仓变化不自动修改原研究判断。持仓数量、研究清单范围和发送模型的资料范围各自明确。

## 历史数据与图表

v0.6 图表只使用当前确定的资产、仓位和情景计算。后续需要连续估值及带日期、金额、来源的外部资金流，才能绘制现金流调整后的单位净值和高点回撤。不能把入金造成的资产上升算作投资收益，也不能把导入前后差异认作交易。

有足够历史且口径确定后再提供净值/基准曲线、回撤曲线、期间收益分布等。缺交易日、资金流或有效价格时标出断点、未覆盖区间和不可计算项，不用平滑线或估算补成完整实盘业绩。

## v0.8 回测验收

1. 固定策略参数版本与输入数据版本，相同输入得到相同信号及结果。
2. 按实际披露和价格可用时间生成信号，不使用当时未知的财报或未来价格；修订资料不能覆盖为过去已知。
3. 明确复权、手续费、税费、滑点、调仓时点及当时适用的交易规则；停牌、涨跌停、无法成交和缺数据不能默认成功成交。
4. 展示净值、基准、回撤、成交明细及未成交原因，收益与风险指标注明定义和样本区间；样本不足时保留未知。
5. 分离用于定规则与评估的区间，记录改参数过程；结果只描述该数据、假设与规则下的模拟表现。
6. Windows 与 Android 可阅读相同结果；计算部署在客户端还是独立分析服务，在历史数据规模明确后决定，不假设手机能直接运行电脑的 Python 程序。

## 与券商接入的关系

规则研究与回测可使用经核验的公开或导入数据，并不等待券商账户直连。真实持仓只读接入需要另外确认客户端、市场、账户类型、权限与完整快照。先有可复核的策略及数据，再讨论实时信号和执行方式；继续保留账户本金与资金流的独立口径。
