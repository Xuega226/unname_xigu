# 未名溪谷 v0.3.1 验收

日期：2026-10-04（Asia/Shanghai）。在 `codex/v0.3-acceptance` 分支，以 v0.2.1 修复提交 `ed0eb21` 为基线，复用已提交的 v0.3 实现 `2116637`，保留第二轮数据完整性修复。应用版本为 `0.3.1+4`，Android 版本码高于 v0.2.1 的 3。

## 大纲复核与交付

版本功能范围和顺序保留：v0.3 完成手动文字 PDF、财务候选人工核验、同口径年度比较、研究历史及复查计划；v0.4 再接入按代码查询和下载年报。OCR、季度批量获取、云同步、后台提醒和全市场扫描仍留待以后。仅补充迁移归档、公司身份关联及原件恢复的验收约束，见 [当前规划](v0.3-plan.md)。

- PDF 原件按 SHA-256 保存，选页文字、页码、报告元数据及校验值进入 schema3；扫描、加密、损坏文件明确拒绝。
- 财务候选须逐项选择并确认，核对期间、单位、口径、指标及本期列；数值与引用定位检查不能代替人工判断。未接受的字段保持 null，利润及经营现金流允许负值。
- 年度比较统一金额单位，期间/口径分组；缺值、断档、重述、重复年度及零/负基数不自动计算误导性同比。
- 编辑研究卡保留历史快照，复查日期、待验证条件和同公司证据随备份保留。有关联的公司身份不能重新分配。
- v1/v2 主文件及备份恢复均先保留不可覆盖的原始字节归档，损坏工作区不被演示覆盖。本地 PDF 读取/校验失败单独提示，已存文字仍可阅读，原件不被覆盖。

## 本次验收

原生验收使用虚构的两页 PDF、临时磁盘目录、模拟模型响应和内存测试凭据，不访问日常研究数据或真实密钥。Android 为独立 API29 x86_64 测试模拟器。

共享完整流程通过界面选择并确认两页原文：第一页收入 100 万元，第二页经营现金流 -20 万元。未确认时不保存；确认后保留两个来源及每个指标的证据。现金、有息负债和扣非利润未接受，保留 null。再保存复查日期和清单、核对研究版本、追加复查、导出备份并在新磁盘工作区导入及重开。

跨端恢复同时核对现金 1000 元、100 股 ×11.50 元、资产 2150 元、净本金 2000 元、盈亏 7.5%，以及股票下跌30%时的账户损失比例 0.16046511627906976。JSON 不包含凭据和 PDF 原件；另一端缺原件仍可阅读选页文字，错误原件因 SHA-256 不同被拒绝，正确原件单独关联后可渲染原页。

Windows 导出文件为 7073 字节，跨端传输前后 SHA-256 均为 `d280e9932890a8ab8b16c34df201b8ca856c3d51bba3d5f4511ac7533c49d9b1`。

发行升级使用旧 v0.2.1 程序实际读取的同份 schema2 测试资料：3 项持仓、5 张研究卡、1 条复查、资产 95000 元。通过领域模型规范化比较迁移前后完整数据，所有字段、ID 和旧复查标记一致；重开后仍保留。两端 `.v2.bak` 与原始输入的 SHA-256 都是 `c59a564acb387fe31db031bbcb97461f0307c216bc07215e9b5535c8668b0afa`。测试只使用隔离 APPDATA、临时目录和本工作区所属模拟器；Flutter 原生测试结束会移除测试包，因此升级验收单独安装旧发行包、恢复旧夹具后再覆盖安装。

Android 默认 Impeller GLES 在此 SwiftShader 驱动上超出 fragment uniform 限制，出现着色器链接错误。发行清单采用[Flutter 官方的 Android 渲染配置](https://docs.flutter.dev/perf/impeller)，关闭 Impeller，与原生验收使用的兼容渲染路径一致；最终 APK 的默认启动与重开另作日志检查。实机性能仍属于未验证范围。Flutter 提示该退出选项未来会弃用，升级 SDK 前需复验。最终启动截图见 [发行版模拟器截图](preview-v0.3/android-v031-emulator.png)。

重装隔离测试包后 UID 改变，ADB 写入夹具曾保留旧 SELinux 标签，应用明确显示读取失败并保留原数据。恢复为测试应用目录的正确标签后，升级与重开正常；没有修改系统 SELinux 策略或用户数据。
