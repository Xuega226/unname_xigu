# v0.7.3：财报准备与 AI 辅助核验

日期：2026-10-05（Asia/Shanghai）。状态：P0 已实现，实际验证与发行状态见 [验收记录](v0.7.3-acceptance.md)。基线为 v0.7.2+12 / schema7，交付目标 v0.7.3+13 / schema8。用户已确认同时覆盖财报选页、报告期间和单位预填，以及财务预核验与报告级确认。

详细行为与异常场景以 [AI 辅助核验需求](ai-verification-requirements.md)为准；后续阶段见 [AI 核验渐进规划](ai-verification-roadmap.md)及 [量化与风险路线图](quant-risk-roadmap.md)。以下保留本轮执行范围与验收门槛。

## 用户完成路径

```text
自动查找年报 / 导入文字 PDF
→ 建议关键页、报告期间、单位与口径，预览并按需调整
→ 确认发送范围，提取与预核验五项财务指标
→ 查看摘要，集中处理异常
→ 一次确认可采纳字段，保存记录及完整证据
```

资料充分、没有冲突的正常报告无需手动找页、重复输入明确期间/单位，或逐项勾选正常财务字段。采用发送范围与主动调用模型，不等于逐项人工核验；最终财务采纳仍由用户一次明确确认。

## P0：本版本必须交付

| 任务 | 交付内容 | 需求对应 |
| --- | --- | --- |
| 恢复常用入口 | 「自动查找年报」与「AI 预核验」直接可见，人工录入仍可使用；自动下载、本地文字 PDF 和既有资料均有可用路径 | AI-01 |
| 报告选页与预填 | 本机定位表格、附注与上下文，主动 AI 请求建议页码、期间、逐表单位与口径；显示依据，允许一次采用及增删/更正 | AI-01、AI-01A |
| 调用范围与成本 | 准备最多一次、提取一次、复核一次，正常完整链路最多三次请求；已有原文可跳过准备；每次请求展示范围，不自动追加付费调用 | AI-02 |
| 财务检查与复核 | 沿用五项指标，程序核对来源/数字/日期/单位等硬规则；单独上下文 AI 复核本期列、语义和口径，非法或未完成结果不可通过 | AI-03、AI-04 |
| 摘要及一次确认 | 正常唯一候选默认纳入，异常、不足、不适用单列；展开原文、处理例外后，一次保存有效字段，缺失不补零 | AI-05、AI-06、AI-07 |
| 状态、保存及失败保护 | 修改输入使旧结论失效；取消和迟到结果隔离，记录与依据一起保存，重复提交不重复写入，失败保留旧数据 | AI-06、AI-08 |
| 证据、兼容与双端 | 保存建议及复核依据、版本、指纹和确认方式；旧记录不追认 AI 复核，迁移与备份保留已有数据，Windows / Android 流程一致 | AI-09、AI-10 |

首期仍是一家公司的一份报告；五项指标为营业收入、扣非净利润、经营活动现金流净额、期末现金及有息负债。合并/母公司、原披露/重述、本期/比较列与各表金额单位必须分清；混合单位不能强拼成现有单单位财务记录。负利润或现金流允许保留。

自动选页意味着建议默认形成可编辑范围，不意味着无人确认发送、财务核验或保存。找不到关键页应显示「本次未定位到」，保留原页与人工选页入口；扫描件不假装已经取到文字。原 PDF 缺失时只能处理已有片段，并说明覆盖范围。

## 开发顺序

1. 确定准备建议、逐项核验结果、确认方式与证据结构，设计持久化及迁移。现有 `aiConfirmed` 保留用户采纳含义，报告级确认不冒充逐项人工对照。
2. 实现本机候选页定位、预览、AI 选页/预填与来源检查，保留人工路径和输入。
3. 整合提取、程序检查与 AI 复核，建立输入失效、取消、失败和在途结果保护。
4. 实现摘要、异常处理、默认集合与一次确认，保证保存前重验及重复提交保护。
5. 完成备份迁移、回归、双端原生和升级验收，再形成发行包与验收记录。

以上步骤均已实现；schema8 与原字节迁移保护一并落地。具体测试、双端原生及发行验收结果单独记录，不以实现完成替代验证。

## 验收与交付门槛

- [详细需求的全部验收场景](ai-verification-requirements.md#4-验收场景)通过，尤其覆盖跨页表头、PDF 页序、期间/单位冲突、错指标、负数、修订及引用失败。
- 正常夹具从报告准备到保存可完整走通：不手动寻找关键页、不重复输入明确期间/单位、不逐项勾选正常字段，一次最终财务确认；建议与复核依据可追溯。
- 无有效候选不生成空记录；候选未经确认不进入评分。取消、参数变化、非法输出、迟到结果、重复点击与保存失败均不破坏已有记录。
- 确认方式和审查状态准确显示；schema7 及当前支持的旧格式迁移、升级重开、双向备份恢复保留金额、证据、研究、量化规则、账户和资金历史。新增格式版本在设计完成后确定，不预先修改 schema。
- 静态分析、针对性测试及既有回归通过；Windows、Android 原生与 390px / 两倍字号流程验证。从 v0.7.2 发行包覆盖升级，构建号须大于12。
- 离线模型夹具与真实模型效果分别报告；真实评估使用分离的开发/最终标注样本，并记录实际调用范围、成本及错误。未做真实验证时明确缺口，不宣称已测准确率。
- 交付 Windows 包、Android APK、SHA-256、验收文档与可审阅变更；文档区分实现、验证和仍规划事项。
