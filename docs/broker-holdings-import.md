# 券商持仓文件导入

## 使用

1. 真实账户从空白工作区开始。在「账户风控 → 导入券商持仓」选择完整账户的 CSV 或 JSON。
2. CSV 另行核对券商名称、账户别名、估值日期与**现金余额**。不使用购买力或融资账户的可用资金代替现金。
3. 每页25项，查看全部新旧数量、市价、现金及将移除的旧持仓。核对完整文件后勾选核验并确认。导入不修改研究和资金流；首次已有资金记录或券商/别名改变时，额外核对入金、出金仍属同一账户。其他账户请先备份当前工作区，再新建空白并维护对应资金记录；不能从当前资产倒推本金。
4. Windows 导入标准 JSON 时，可勾选每 15 秒自动读取。应用运行且处于前台、没有打开对话框或其他保存/联网任务时检查。应用关闭后停止；再次打开恢复已绑定的本机设置。人工修改持仓、现金或估值日期后关闭自动读取，需要重新预览绑定。
5. 在「券商持仓导入」区域查看来源、快照时间、上次导入及错误状态；可立即检查或关闭自动读取。

**这是文件导入。应用还不能登录券商账户，也不会自行产生新文件。** 自动读取需要外部券商适配器持续写入符合约定的 JSON，目前尚未接入真实券商适配器。CSV 仍需用户从券商导出，并核对账户信息。

只支持 CNY 普通股票账户的沪深北 A 股。非零持仓需正市价，数量必须是非负整数；零股数行不计持仓。未提供行业时保留该代码已有行业，否则显示资料不足。重复证券拒绝，不猜测合并不同子账户。一次导入最多 2 MB / 1000 项。

导入完整快照会移除文件中没有的旧持仓。空持仓可手动确认清空，不能自动清空。自动读取失败保留旧数据；文件不完整、旧时间、旧估值日期、同时间不同内容及不同账户不自动覆盖。

## CSV

支持严格 UTF-8（可带 BOM）、带 BOM 的 UTF-16 和明确确认后的 GBK。没有 BOM 且不能作为 UTF-8 解码时，必须点按「确认使用 GBK」，不能自动替换错误字节。GB18030 四字节、截断编码及 XLS / XLSX 不支持，请另存为 UTF-8 CSV。

支持逗号、制表符、分号、双引号转义、CRLF 和引号内的分隔符。无法确定分隔符时拒绝，保留旧数据。

| 字段 | 可识别表头 |
| --- | --- |
| 证券代码 | 证券代码、股票代码、代码、code |
| 名称 | 证券名称、股票名称、名称、name |
| 总持仓数量 | 股票余额、证券数量、持仓数量、持股数量、quantity |
| 市价 | 市价、当前价、最新价、最新价格、price |
| 行业（可选） | 行业、industry |

未知或歧义表头会进入「核对 CSV 列映射」。结合样例行明确选择代码、名称、总持仓数量、市价及可选行业；已识别的文件也可调整映射。一个列不能同时用于多个字段。其他列忽略。已知的可卖量、可用余额或成本价列不能映射为总数量或市价，文件缺少所需口径时不能导入。

虚构样例见 [CSV 样例](../examples/broker-holdings.csv)。代码字段保留六位文本，不能变成数值 `1`；也接受 `000001.SZ`，交易所必须匹配。

## 标准 JSON 快照 v1

虚构样例见 [JSON 样例](../examples/broker-snapshot.json)。供后续官方券商接口或本机适配器生成，应用不向任何服务上传文件。

```json
{
  "snapshotVersion": 1,
  "complete": true,
  "accountType": "cash_equity",
  "currency": "CNY",
  "broker": "虚构测试券商",
  "accountAlias": "测试主账户",
  "priceDate": "2026-10-01",
  "capturedAt": "2026-10-01T09:00:00+08:00",
  "cash": 5000,
  "holdings": [
    {"code": "000001", "name": "虚构测试证券", "quantity": 100, "price": 10}
  ]
}
```

- `complete`：适配器确认全部持仓成功取得后才输出 true；分页失败不能输出部分账户。
- `accountType`：只允许普通现金股票账户 `cash_equity`，融资账户不能标成普通账户。
- `broker` / `accountAlias`：稳定的券商名称和本机账户别名，用于防止自动换账户；不要使用完整账号或凭据。别名不能替代券商接口中的实际账户归属核验。
- `priceDate`：全部持仓价格对应的北京时间估值日期，YYYY-MM-DD。首次导入空账户允许最近交易日；已有资产时不回退。
- `capturedAt`：完整账户快照的获取时间，必须包含 Z 或明确时区。相同时间不应产生不同内容。
- `cash`：与该完整快照一致的现金余额，人民币元。不填写净资产、证券市值、购买力或含融资额度的可用资金。
- `holdings`：完整非负多头股票持仓；`code` / `name` / `quantity` / `price` 必填。`exchange` 可选 SH/SZ/BJ，`industry` 可选。价格不得以成本价替代。
- `price`：人民币元每股；`quantity`：股；资金流、本金和券商浮盈不推导或覆盖。

推荐外部适配器先写临时文件，校验账户与完整性后再原子替换绑定文件。只在新完整快照成功后更新捕获时间。应用检查大小、读取前后的文件状态、格式和来源账户，但不验证文件内容是否真实来自券商。

## 备份与恢复

研究备份 schemaVersion 7 包含导入元数据和历史、量化参数及资金流水，仍为明文。完整账号、登录密码、接口密钥与本机文件路径不属于快照约定，不能写入备份。文件自动读取设置独立保存为应用数据目录下 `broker-file-settings.json`，换设备不自动启用，需要重新选择文件并核对。成功恢复备份时关闭原绑定，避免新文件再次覆盖恢复的持仓；取消或保存失败保留原绑定与工作区。

「持仓导入历史」保留最近20条，成功记录包含前后持仓快照，失败记录仅含固定安全原因。完整差异每页25项。点按「恢复此记录之前」并确认后，只恢复现金、持仓、估值日期与来源状态，保留当前公司研究、资料、财务、复查、研究版本、资金和风险偏好；关闭自动读取。取消或保存失败保持全部旧状态。容量不足以保留必要恢复快照时拒绝新操作。

历史恢复不同于整份备份恢复：后者替换整个工作区。schema7 兼容旧版1–4、6；多账户实验格式 schema5 明确拒绝，不能用来覆盖此单账户工作区。持仓导入与历史恢复保留当前量化参数、历史行情和资金流水。

持仓首次接入真实账户尚未联调。选定券商后，需实际验证接口权限、资产类型、现金口径、完整持仓、断线/重连、同日成交变化及两端部署方式。
