# AI 辅助核验需求

日期：2026-10-05（Asia/Shanghai）。状态：首期 P0 已按 v0.7.3 实现，具体验证及发行状态见 [验收记录](v0.7.3-acceptance.md)。基线为 v0.7.2；用户确认同时覆盖财报选页、报告期间和单位预填，以及财务预核验与报告级确认。执行依据见 [v0.7.3 版本规划](v0.7.3-plan.md)，后续方向见 [渐进规划](ai-verification-roadmap.md)。

## 1. 用户目标

用户希望减少反复输入报告信息、逐项寻找数字和重复勾选的工作，让 AI 承担更多阅读与核验，自己主要查看摘要、处理异常并作最终确认。

首期完成后，一份资料充分、没有冲突的报告应能走通：

```text
打开公司资料 → 自动查找年报或导入文字 PDF
→ 获取建议页码、报告期间和单位 → 预览并按需调整
→ 开始 AI 预核验（确认发送范围） → 查看五项指标的核验摘要
→ 一次确认可采纳字段 → 保存财务记录与核验依据
```

正常流程不再要求用户逐项勾选五个字段。原文始终可展开；异常不会混在正常项目中当作已通过。

## 2. 范围与优先级

| 优先级 | 需求范围 | 交付边界 |
| --- | --- | --- |
| P0：首期必做 | 一家公司的单份文字财报，五项财务指标的 AI 预核验、摘要、异常处理与一次确认 | 沿用现有 DeepSeek 配置，Windows / Android 共用流程；保存前仍需用户主动确认 |
| P0：报告准备 | 自动查找年报入口可直接发现，建议财报页码，识别并预填报告期间、表头口径和单位 | 同时覆盖自动下载与本地文字 PDF；建议可预览、增删和更正，保留依据，不重复手输明确的信息 |
| P0：操作简化 | 正常候选默认纳入待确认集合，资料准备与财务预核验连贯衔接 | 不要求逐页和逐字段重复勾选；存在歧义时集中提示 |
| P1：后续减负 | 跨报告异常队列、多年度批次处理 | 首期仍以一份报告为单位，不自动处理所有报告 |
| P2：条件开放 | 通过项目标注验收后的有限自动采纳与抽查、暂停、撤销 | 另行定义采纳策略及数据状态，不随首期启用 |

五项指标为营业收入、扣非净利润、经营活动现金流净额、期末现金、有息负债。原文指标名称必须保留，不能把净利润替成扣非净利润、总负债替成有息负债，或混淆货币资金与现金及现金等价物。

首期在本机解析文字 PDF 并准备选页建议，模型仅接收界面已展示范围内的文字。不新增扫描件 OCR、后台自动付费请求或全市场研究流程。投资判断、量化规则参数与账户资金操作沿用现有用户决策方式。

## 3. 首期功能要求

### AI-01：入口与预填

「资料与财务」的「资料原文」页直接显示「自动查找年报」，不只放在添加菜单里；财务页直接显示「AI 预核验」，人工录入保留为次级入口。

用户选择一份报告后，复用已知公司、公告身份和披露日，并从正文及表头识别报告期间、报表口径及单位，展示出处与待确认状态。公告年度只能作为期间建议，不能代替正文检查；不能把披露日当成报告截止日、把比较年度当成本期，或从文件名猜金额单位。未知字段保持未知；修订公告不默认判为原披露。用户无需手输已明确的起止日期；同一年度存在多个版本时，必须展示版本差异供选择。

### AI-01A：选页与预填建议

本机先按目录、表名、指标原名和日期/单位线索定位候选页；用户主动点击「AI 选页与预填」后，可用一次请求进一步识别这些候选片段。请求前展示候选页码、发送片段、字数、模型和预计请求次数，允许调整；不静默发送整份财报。

输出覆盖营业收入、扣非净利润、现金流、现金及有息负债所需的表格和附注，并带上必要的表头、单位和相邻续表页。每项建议给出真实 PDF 页序、页面标题/摘录和推荐理由；区分 PDF 页序与印刷页码，预览须跳到对应原页。程序验证页码存在、引用可定位、日期及单位可解析，模型不能凭空指定页码。

建议页默认组成可编辑的范围，用户可一次采用、增加或移除；不要求逐页勾选「已人工核验」。期间、单位与口径建议直接带入后续界面，只有缺失或冲突才集中要求处理。报告单位与各表单位分别核对，表头冲突不套用统一单位。自动准备不等于财务值已核验；最终数值仍经过提取、程序检查、AI 复核和报告级确认。

找不到表格、必要续表缺失或扫描件无法取字时，说明本次未定位到，不声称报告未披露；保留搜索、原页浏览和人工选页。不得为凑齐五项指标补造页码、日期或单位。现有 PDF 文件、页数及导入选页限制继续适用；模型范围超过 60000 字时提示缩小范围，不静默截断表头或追加请求。已经保存的资料仍可从原 PDF 重新建议选页；原 PDF 不可读取时只处理已有片段，并明确覆盖范围。

### AI-02：资料范围与请求

开始前显示所选报告、页码/片段、字数、目标口径、当前模型与预计请求次数。报告准备最多一次 AI 请求，用户也可使用本机建议或人工选页跳过该请求；后续一次主动预核验通常包含一次提取和一次复核。因此完整正常链路最多三次请求，已准备好原文时通常两次，按已有模型账户计费；不为五个指标各发起一轮复核，不自动切换到其他模型。

没有可发送文字、缺少本地模型配置或超出现有 60000 字限制时，不发送请求。准备阶段允许期间和单位尚未知，由建议补全；进入财务预核验前必要输入须有效。提取没有可用候选时，直接展示不足或错误，不继续复核请求。用户修改范围后重新开始，不静默拆成额外付费批次。模型输出或原文中的指令不得改变发送范围、触发调用或直接保存数据。

### AI-03：提取与程序检查

AI 输出原始指标名称、原始数字、单位、报告期间、报表口径及来源引用。数值解析、明确的单位换算和后续因子计算由程序执行；不接受 AI 猜测或自行推算的缺失数字。

程序检查公司及来源绑定、引用存在、原始数值与摘录对应、日期顺序、目标期间、单位、口径和重复/冲突。程序硬校验失败的候选不能通过简单勾选强制采纳。负利润和负现金流可以是正常数据；缺失值保持缺失。

### AI-04：AI 复核

用单独上下文再次核对原文、本期与比较列、指标含义、期间、单位、合并/母公司及原披露/重述口径。可以携带待复核候选，但不把首次模型的「已通过」判断或置信度作为依据。

复核须返回逐项结论、理由和原文依据；该依据也须通过程序的来源与摘录检查。缺表头、证据不足、模型意见冲突、输出非法或请求未完成，标为待处理或未完成，不能标成通过。同一模型的两次请求不视为相互独立的事实证明。

### AI-05：摘要与默认集合

摘要按「可确认」「待处理」「资料不足」「不适用」显示五项指标，并显示各类数量。每项可查看原始名称/数字、单位、期间、来源页码、程序结果、AI 复核理由及问题。

唯一、无冲突且程序检查与 AI 复核均通过的候选默认纳入待确认集合；用户可排除，不必重复逐项勾选。待处理项目不默认选入，不展示无条件的「全部核验通过」结论。

首期一条财务记录仍要求公司、报告期间、披露日、口径及单位一致。混合单位或冲突版本不能强拼成一条记录；提示选择一致来源或使用现有人工流程。全部缺失或均不可采纳时，不生成空财务记录。

### AI-06：一次确认与保存

用户点击「确认并保存可采纳字段」时，展示最终字段集合、金额与出处，以及本次排除、缺失和未处理项目。确认表示用户采纳该摘要中的数字，不要求用户声称已逐项对照全部原页。

保存前再校验输入、当前报告与工作区未改变；一次成功保存同时写入财务记录及本次核验依据。已存在的记录不静默覆盖。相同报告、字段及完整证据重复提交时，提示已保存，不生成重复记录；证据或版本不同则按冲突处理。

至少有一个可采纳字段才能保存。部分字段缺失允许保存其余有效字段，量化页继续按既有缺失规则处理。候选及 AI 预核验结果在用户确认前不进入财务评分。

### AI-07：异常处理

错公司、引用不存在、数值解析失败、无效日期等硬错误须更正来源或输入并重新检查。对于本期列、语义或口径无法确认的项目，用户可查看原文、选择其他候选、补资料、排除该项或转人工录入。

修改公司、来源、期间、单位、口径、披露版本或金额后，原核验结论失效，不能沿用旧的通过状态。用户处理了语义例外时，记录选择及依据；不能用该操作绕过程序硬错误。特殊行业的不适用指标单独提示，不强行计算。

### AI-08：进度、取消与失败

页面区分准备建议中、待采用范围、提取中、程序检查、AI 复核中、待确认、需要处理、保存中、已采纳及未完成。重复点击不会并发创建相同任务；旧请求的迟到结果不能修改新的任务或工作区。建议失败可转人工选页，预填不清空用户已明确输入的值；建议与人工值冲突时展示差异。

用户可停止等待；取消、关闭、模型超时/截断/非法输出和保存失败保留旧财务记录。已发出的请求可能已计费，停止等待不承诺退款。失败后由用户决定是否重试，不自动发起新付费请求。保存失败可重试，但不得重复写入已成功保存的批次。

### AI-09：证据、状态与兼容

保留原文来源、页码、摘录、原始数字、报告元数据、选页与预填建议及其依据、模型与准备/提取/复核模板版本、程序检查版本、输入指纹、各项结果、人工处理依据及采纳时间。

明确区分「AI 预核验通过」「用户报告级确认」「旧版逐项人工核验」及后续「自动采纳」。报告级确认不能被展示为逐项人工对照原页。现有 `aiConfirmed` 仍说明 AI 候选经用户确认采纳，新增确认方式与审查记录须另行保存；不推断旧记录曾接受 AI 复核。

新增持久化字段进入版本化备份；如需升级数据格式，提供迁移、旧数据保护及双端恢复验收。第一阶段不开放无人工确认的自动采纳，也不改历史资料的原始披露时点。

### AI-10：双端与操作成本

Windows 与 Android 显示相同状态、金额、问题和证据。390px 手机及两倍字号可阅读摘要、展开原文、处理异常和完成确认，常用入口与最终动作不因折叠而难以发现。

仅发送用户选定的原文与必要出处，不发送账户持仓、资金或密钥正文；密钥沿用本机安全存储。服务返回 usage 时记录实际消耗，未返回时标为未知，不伪造 token 或费用数字。

## 4. 验收场景

| 场景 | 预期结果 |
| --- | --- |
| 自动下载或本地导入同一文字年报 | 建议关键表格、附注及必要续表；页序可跳转原页，期间和单位带入下一步，无需手输明确字段或逐页勾选核验 |
| 表头跨页、印刷页码不同、本期与比较年度并列 | 保留跨页上下文，跳转真实 PDF 页序；期间取本期并显示依据，无法确定时待处理 |
| 各表单位不同、公告元数据与正文冲突 | 保留逐表单位和差异，不全局套用单位；冲突不默认采纳，不改用户输入 |
| 找不到关键页、扫描件、原文件缺失或文字超限 | 明确未定位/无法取字/覆盖不足，提供人工路径；不补造资料，不静默扩大或截断发送范围 |
| 五项正常且同口径、同单位 | 五项默认纳入待确认集合；无需逐项勾选，一次明确确认后保存，全部证据可追溯 |
| 原文含本期和上期列 | 正确本期候选可确认；识别为错列或无法确定的候选进入待处理，不能默认采纳 |
| 净利润/扣非净利润、总负债/有息负债混淆 | 显示具体语义问题，不因数值确实出现在原文而通过 |
| 负利润或负现金流，其他字段缺失 | 保留原始负号，负数不自动判错；缺失不补零，允许确认其余有效字段 |
| 错公司、错单位、无效日期、假引用 | 程序硬阻断；即使模型声称通过也不能保存该候选 |
| 多个版本、修订或原披露/重述不明 | 展示差异及待处理原因，不覆盖旧记录，不把更正数值回填为历史已知 |
| 全部缺失、特殊行业不适用、原文不足 | 明确不足/不适用，不能保存空记录或生成虚假评分 |
| 改参数、换报告、取消、迟到结果、重复点击 | 旧核验失效，旧任务不写入新上下文，取消无新增，成功批次不重复保存 |
| 请求失败或保存失败 | 不产生已通过/已采纳假状态；旧数据不变，重试由用户发起 |
| 备份、升级与双端恢复 | 金额、证据和确认方式一致，旧资料不被追认为 AI 复核通过 |

测试区分程序/界面夹具验收与真实模型效果评估。程序硬阻断样例均须被拦截，正常批量确认与失败保护流程均须通过；真实模型使用分开的开发和最终验收标注样本，记录错列、错指标、错单位等错误，不以模型自报分数替代参考答案。首期不承诺真实模型准确率。

## 5. 成功标准与实施顺序

记录正常报告需要的手动找页次数、重复输入次数、用户确认次数、逐项勾选次数、待处理量、模型请求数及实际可取得的消耗信息，验证减少操作的目标。首期资料充分的正常报告无需手动找页和重复输入明确的期间/单位，最终财务采纳为一次报告级确认，正常字段的逐项勾选为零；发送前采用范围属于主动请求操作，不冒充财务核验。不得以降低问题提示数量掩盖错误。

开发顺序为：建议/核验结果与证据格式 → 本机定位、AI 选页与预填 → 程序校验和输入失效机制 → AI 复核服务 → 摘要/异常/一次确认界面 → 保存、备份及双端验收。实现前确定新增持久化字段与迁移方案，保留单账户及现有量化计算定义。

用户已确认首期同时覆盖财报准备与财务核验，以上 P0 归入 v0.7.3。跨报告/多年度批次列入后续 v0.7.4 规划；受控自动采纳始终属于独立的条件阶段，不绑定版本号。
