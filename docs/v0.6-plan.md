# 未名溪谷 v0.6：单账户风险图表与可恢复导入

日期：2026-10-05（Asia/Shanghai）。根据用户“不需要做多账户”的要求修订，基线为已验收的 v0.5.1+9。本文是后续开发规划，尚未在当前分支实现或验收。

用户追加风险分析图表需求，纳入本轮 P0；量化接入阶段见 [量化与风险路线图](quant-risk-roadmap.md)。

## 范围

继续使用一个工作区对应一个 CNY 普通股票账户的模型。不加入账户列表、新建账户、账户切换、多账户资金隔离或资产聚合。券商名称和账户别名继续作为导入来源核对信息，不作为可管理的多个账户。

| 优先级 | 内容 | 验收结果 |
| --- | --- | --- |
| P0 | 风险分析图表 | 现金/股票资产构成、个股/行业集中度、压力情景曲线及相对本金盈亏与偏好标记 |
| P0 | 导入历史、全量差异与撤销 | 能查看导入前后现金、日期、数量、市价及新增/移除项，误导入后可恢复持仓 |
| P0 | CSV 编码、分隔符与人工列映射 | 支持严格 GBK、逗号/制表符/分号；未知或歧义表头由用户明确选择 |
| P0 | 单账户资金归属保护 | 来源变化仍须人工核对，买卖及资产变化不修改入金、出金或推导本金 |
| P0 | 双端原生与升级验收 | 从当前 v0.5.1 升级、重开与 Windows 导出到安卓恢复保持全部有效字段 |
| P1 | 读取状态与估值口径 | 区分等待、暂停、错误、陈旧及保存失败，说明可执行的下一步 |
| P1 | 持仓进入公司研究 | 按交易所与代码关联已有研究卡，缺资料时提供人工补全入口 |
| 外部依赖 | 一个真实券商导出文件或只读接口 | 客户端、市场、账户类型、完整样例和权限确认后另行联调 |

P0 为本轮交付要求，P1 分批完成。真实接口尚未确认时，先完成文件导入的通用能力并明确记录联调缺口，不将文件自动读取称为账户直连。

## 风险分析图表

Windows 与 Android 的账户风控页使用同一套现有领域计算，图表配备数值明细、估值日期和数据状态，可点击或点按查看具体数值，不只依靠颜色传达含义。

| 图表 | 数据与交互 | 口径 |
| --- | --- | --- |
| 资产构成环形图 | 现金与股票市值，显示金额及占比 | 分母为账户资产；无资产时显示空状态，不能生成100%现金 |
| 个股/行业水平条形图 | 按市值占比排序，点按显示金额、占比及证券；全量分页或展开 | 分母为账户资产，包含现金对占比的影响；行业缺失单列“行业资料不足” |
| 压力情景折线图 | 横轴所有股票假设跌幅，纵轴对应账户损失比例，滑块联动选中点；显示损失金额与情景后资产 | 现金不变、股票同幅下跌，复用 `stressLoss`；是指定情景，不是预测、VaR或最大损失 |
| 相对本金盈亏刻度图 | 当前盈亏比例与用户亏损偏好标记，同时显示净本金及金额 | 分母为净投入本金；本金非正时显示无法计算；不能与压力图的资产分母混用 |

个股/行业项多时保留全部明细，若展示“其他”聚合项须能展开。小屏纵向排列，桌面可并排；大字体仍能查看完整标签和数值。保留现有文字及表格解释，图表更新不保存持仓、不改资金、不自动生成买卖指令。

当前只有累计入金/出金及单次估值，导入历史不是完整交易日估值序列。本轮不绘制伪造的历史净值、高点回撤、年度收益或相关性曲线；历史数据与带日期的资金流基础按路线图推进。资料不足时明确说明缺少什么数据。

## 导入历史与撤销

成功导入保存持仓、现金、估值日期和来源元数据的前后快照、操作时间与结果。失败仅记录安全原因和必要元数据，同一失败去重，不保存文件原文、凭据或本机路径。差异按证券并集计算，全部项目每页25项可查看；以“数量增加/减少”等观察描述呈现，不据此断言成交或公司行为。

撤销须预览和确认，只恢复持仓、现金、估值日期及对应来源状态，保留当前公司研究、资料、财务、研究版本、复查任务、入金、出金及风险偏好。恢复成功关闭自动读取，明确显示恢复了历史快照，需要重新核验才能绑定。取消或保存失败不得改变工作区、历史或绑定。

历史初始上限为20条、序列化历史400万字符，并满足现有完整工作区备份大小限制。优先保留最新可撤销操作；若仍无法容纳新操作所需的恢复快照，则拒绝新导入并说明原因。不能先覆盖持仓再发现历史保存失败。历史进入工作区备份，原滚动 `.bak` 继续承担磁盘恢复。

## CSV 兼容

保留 UTF-8 / BOM UTF-16 和现有列名识别，增加严格 GBK 及分隔符识别。编码不能可靠识别时明确要求用户选择或另存；不使用替换字符掩盖解码错误。GB18030 四字节和 XLS/XLSX 不在本轮要求。

未知或歧义表头提供代码、名称、总持仓数量、市价的人工映射和样例预览，现金、日期和来源仍需核验。可卖量不能替代总数量，成本价不能替代市价，购买力不能替代现金；缺值和重复代码不猜测。首轮不要求保存来源模板，真实脱敏样例验证后再决定模板范围。

## 单账户资金口径

沿用 v0.5.1 的资金归属确认：首次已有资金记录、券商或账户别名变化时，显式确认原入金与出金属于同一账户。改来源不自动创建账户，不将历史快照恢复解释为资金转入或转出。

不同实际账户的数据仍通过先导出当前资料、再新建空白工作区分别维护；本轮不提供账户间切换或聚合。净本金继续为入金减出金，不能从当前资产、成本或导入前后差异反推。

## 迁移与实现约束

新增持久化历史时按需升级 schema，兼容 v1–v4，迁移前保留精确原始字节；真实工作区的既有资金、来源、研究与 PDF 关联不变。版本构建号必须大于当前9，保证安卓可以覆盖升级。

另一工作区的 v0.6 实现含多账户模型及 schema5；只复用可独立保留的 CSV 解析、差异和历史设计，不能整体替换当前领域模型、套用账户迁移或把已有验证记录视为本轮验收。整合时保留 v0.5.1 的时间与来源校验、完整预览、资金归属确认、停止在途读取、备份恢复关闭绑定及 v0.4.3 的财报修复。

## 验收

1. 单账户导入、来源变化、资金确认与失败保存保持正确；界面和备份不引入多账户管理。
2. CSV 中文、六位代码前导零、引号与三种分隔符通过；错误编码、歧义映射和数量/价格语义不匹配拒绝，旧数据保持。
3. 80项全量差异四页可查看，现金变化和新增/移除完整；取消不创建历史、不保存持仓。
4. 导入后修改研究与资金，再撤销导入，恢复账户快照而保留这些后续修改；恢复后源文件变化也不自动覆盖。
5. 历史数量/容量、失败去重、损坏备份、主文件与仅剩旧备份迁移均验证；历史和工作区一起保存，失败不产生半次操作。
6. Windows 实际文件读取、周期更新、停止和重开，以及 Android 原生导入、重开、跨端备份和覆盖升级通过。系统文件选择器实测与注入选择结果分别记录。
7. 静态分析与相关回归通过，两端发行包、校验和、验收文档及可审阅提交齐全。真实券商联调缺口明确记录。
8. 用可手算样例核对全部图表，现金占比、个股/行业合计、压力损失和本金盈亏与原公式一致；空账户、纯现金、非正本金、缺行业及大量持仓有明确显示。
9. 桌面、手机、大字体的点按/滑块/全量明细流程通过；未核验及陈旧数据的状态可见，图表操作不改变工作区。净值/回撤缺历史时保持未知。

融资/负债、多币种、自动交易、全市场扫描、云同步与跨设备后台服务仍为独立后续需求。量化规则、回测及历史净值/回撤按路线图推进，继续采用单账户。
